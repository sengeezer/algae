## Why It Surfaces

This is a direct polygon-metrics prompt. The clean solution computes the polygon area with the shoelace formula, computes perimeter by summing adjacent edge lengths, and compares the two with a small tolerance.

## Worked Example

- Triangle `(0, 0)`, `(5, 0)`, `(0, 12)` is equable because area is `30` and perimeter is also `30`.
- Rectangle `(0, 0)`, `(6, 0)`, `(6, 4)`, `(0, 4)` is not equable because area is `24` while perimeter is `20`.

## Reference Implementations

<ExamplePair>

```js
function equableShapes(points) {
  if (!Array.isArray(points) || points.length < 3) {
    throw new RangeError("Expected at least three ordered polygon vertices");
  }

  let twiceArea = 0;
  let perimeter = 0;

  for (let index = 0; index < points.length; index += 1) {
    const current = points[index];
    const next = points[(index + 1) % points.length];
    if (!current || !next || !Number.isFinite(current.x) || !Number.isFinite(current.y) || !Number.isFinite(next.x) || !Number.isFinite(next.y)) {
      throw new RangeError("Vertices must contain finite x and y coordinates");
    }

    twiceArea += current.x * next.y - next.x * current.y;
    perimeter += Math.hypot(next.x - current.x, next.y - current.y);
  }

  const area = Math.abs(twiceArea) / 2;
  return Math.abs(area - perimeter) < 1e-9;
}
```

## Follow-up Questions

- Why does the shoelace formula require ordered vertices?
- How should the equality test change when input coordinates are floating-point measurements?
- Can a self-intersecting polygon be meaningfully treated as equable under this definition?

## Common Pitfalls

- Forgetting the closing edge from the last vertex back to the first.
- Comparing floating-point area and perimeter with exact equality in noisy inputs.
- Applying the shoelace formula to unordered points.

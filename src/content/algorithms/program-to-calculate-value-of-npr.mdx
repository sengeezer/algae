## Why It Surfaces

This is the direct counting version of "choose `r` out of `n` when the positions stay distinct." The interview hinge is simple: answer the order question first, then apply the matching formula.

## Worked Example

If 5 candidates are competing for gold, silver, and bronze, order matters because each podium spot is different. The count is `P(5, 3) = 5 * 4 * 3 = 60`.

## Reference Implementations

<ExamplePair>

```js
function nPr(n, r) {
  if (!Number.isInteger(n) || !Number.isInteger(r)) {
    return 0n;
  }

  if (n < 0 || r < 0 || r > n) {
    return 0n;
  }

  let result = 1n;

  for (let used = 0; used < r; used += 1) {
    result *= BigInt(n - used);
  }

  return result;
}
```

## Follow-up Questions

- Explain why `C(n, r)` divides this same count by `r!`.
- Return the answer modulo `1_000_000_007` instead of as an exact integer.
- Switch from counting arrangements to generating the actual permutations.

## Common Pitfalls

- Using `nCr` even though the positions are distinct.
- Forgetting that `r > n` is invalid and should return zero arrangements.
- Computing full factorials and overflowing earlier than necessary.

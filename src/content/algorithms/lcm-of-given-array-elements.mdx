## Why It Surfaces

This is the natural follow-up once a candidate knows the two-number lcm formula. The trick is to keep a running answer and repeatedly combine it with the next element using `lcm(a, b) = (a / gcd(a, b)) * b`.

## Worked Example

- For `[1, 2, 8, 3]`, the running lcm becomes `1`, then `2`, then `8`, then `24`.
- For `[2, 7, 3, 9, 4]`, the running lcm progresses to `2`, `14`, `42`, `126`, and finally `252`.

## Reference Implementations

<ExamplePair>

```js
function gcd(left, right) {
  let a = Math.abs(left);
  let b = Math.abs(right);

  while (b !== 0) {
    [a, b] = [b, a % b];
  }

  return a;
}

function lcmOfGivenArrayElements(values) {
  if (!Array.isArray(values) || values.length === 0) {
    throw new RangeError("Expected a non-empty array of positive integers");
  }

  let runningLcm = 1;

  for (const value of values) {
    if (!Number.isInteger(value) || value < 1) {
      throw new RangeError("Array elements must be positive integers");
    }

    runningLcm = (runningLcm / gcd(runningLcm, value)) * value;
  }

  return runningLcm;
}
```

function gcd(left: number, right: number): number {
  let a = Math.abs(left);
  let b = Math.abs(right);

  while (b !== 0) {
    [a, b] = [b, a % b];
  }

  return a;
}

export function lcmOfGivenArrayElements(values: number[]): number {
  if (values.length === 0) {
    throw new RangeError('Expected a non-empty array of positive integers');
  }

  let runningLcm = 1;

  for (const value of values) {

      throw new RangeError('Array elements must be positive integers');
    }

    runningLcm = (runningLcm / gcd(runningLcm, value)) * value;
  }

  return runningLcm;
}

## Follow-up Questions

- Why is `(runningLcm / gcd(runningLcm, value)) * value` safer than `runningLcm * value / gcd(...)`?

## Common Pitfalls

- Treating array lcm as `product / gcd(all values)`, which does not hold for more than two numbers.
- Forgetting to validate that the list is non-empty and positive under the standard formulation.
- Multiplying before dividing and inflating intermediate values unnecessarily.

## Why It Surfaces

Abundant-number prompts usually serve as the entry point to more involved divisor-sum problems. The standalone predicate is still worth keeping because later tasks like non-abundant sums depend on it directly.

## Worked Example

`12` is abundant because its proper divisors `1`, `2`, `3`, `4`, and `6` sum to `16`, which is greater than `12`. `21` is not abundant because its proper divisors sum to only `11`.

## Reference Implementations

<ExamplePair>

```js
function sumProperDivisors(value) {
  if (value <= 1) {
    return 0;
  }

  let sum = 1;

  for (let divisor = 2; divisor * divisor <= value; divisor += 1) {
    if (value % divisor !== 0) {
      continue;
    }

    sum += divisor;
    const pairedDivisor = value / divisor;

    if (pairedDivisor !== divisor) {
      sum += pairedDivisor;
    }
  }

  return sum;
}

function abundantNumber(value) {
  if (!Number.isInteger(value) || value < 1) {
    throw new RangeError('Value must be a positive integer');
  }

  return sumProperDivisors(value) > value;
}

console.assert(abundantNumber(12) === true, '12 is abundant');
console.assert(abundantNumber(18) === true, '18 is abundant');
console.assert(abundantNumber(21) === false, '21 is not abundant');
```

## Follow-up Questions

- Return the abundance amount `sumProperDivisors(n) - n`.
- Build the list of all abundant numbers up to a limit.
- Use the predicate as the first step in `Problem 023` style reachability questions.

## Common Pitfalls

- Including `n` itself in the proper-divisor sum and inflating every result.
- Reusing `Problem 023` pairwise logic when the standalone predicate is all the prompt needs.
- Missing the special case where `1` has proper-divisor sum `0`.

## Why It Surfaces

This is an optimization-plus-construction problem. The decisive observation is that any valid sequence with gcd `g` can be written as `g * [x1, x2, ..., xm]`, so `g` must divide `n` and still leave enough sum for the smallest strictly increasing base sequence.

## Worked Example

- For `n = 24` and `m = 3`, the minimum base sum is `1 + 2 + 3 = 6`, so the gcd cannot exceed `24 / 6 = 4`. Since `4` divides `24`, the lexicographically smallest optimal sequence is `[4, 8, 12]`.
- For `n = 6` and `m = 4`, the minimum required sum is `10`, so no valid increasing sequence exists and the answer is `[-1]`.

```js
function seriesWithLargestGcdAndSumEqualsToN(n, m) {
  if (!Number.isInteger(n) || !Number.isInteger(m) || n < 1 || m < 1) {
    throw new RangeError("Expected positive integers for n and m");
  }

  const minimumSum = (m * (m + 1)) / 2;
  if (minimumSum > n) {
    return [-1];
  }

  const gcdLimit = Math.floor(n / minimumSum);
  let bestGcd = 1;

  for (let divisor = 1; divisor * divisor <= n; divisor += 1) {
    if (n % divisor !== 0) {
      continue;
    }

    if (divisor <= gcdLimit) {
      bestGcd = Math.max(bestGcd, divisor);
    }

    const pairedDivisor = n / divisor;
    if (pairedDivisor <= gcdLimit) {
      bestGcd = Math.max(bestGcd, pairedDivisor);
    }
  }

  const sequence = [];
  for (let value = 1; value < m; value += 1) {
    sequence.push(bestGcd * value);
  }

  const usedSum = (bestGcd * m * (m - 1)) / 2;
  sequence.push(n - usedSum);
  return sequence;
}
```

## Follow-up Questions

- Why does `[g, 2g, ..., (m - 1)g, last]` give the lexicographically smallest sequence for a fixed gcd `g`?
- How would you prove that the final element is still strictly larger than the previous one?
- Could you derive the maximum gcd directly without checking divisors one by one?

## Common Pitfalls

- Forgetting the feasibility bound from the minimum increasing sum `1 + 2 + ... + m`.
- Maximizing the last element instead of maximizing the shared gcd first.
- Returning any valid sequence instead of the lexicographically smallest one among optimal answers.

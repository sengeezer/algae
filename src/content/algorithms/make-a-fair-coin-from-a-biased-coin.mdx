## Why It Surfaces

This is a classic probability-construction problem. Even if one call to the source coin is biased, two calls create four ordered pairs. The pairs `(0, 1)` and `(1, 0)` have the same probability, so you can map one to `0`, the other to `1`, and ignore the equal pairs.

## Worked Example

Suppose the biased coin returns `0` with probability `0.6` and `1` with probability `0.4`.

- `P(0, 1) = 0.6 * 0.4 = 0.24`
- `P(1, 0) = 0.4 * 0.6 = 0.24`

Because those two kept cases are equiprobable, returning `0` for `(0, 1)` and `1` for `(1, 0)` yields a fair result.

## Reference Implementations

<ExamplePair>

```js
function makeAFairCoinFromABiasedCoin(biasedCoin, maxAttempts = 1_000_000) {
  if (typeof biasedCoin !== 'function') {
    throw new TypeError('biasedCoin must be a function that returns 0 or 1');
  }

  if (!Number.isInteger(maxAttempts) || maxAttempts <= 0) {
    throw new RangeError('maxAttempts must be a positive integer');
  }

  for (let attempt = 0; attempt < maxAttempts; attempt += 1) {
    const first = biasedCoin();
    const second = biasedCoin();

    if ((first !== 0 && first !== 1) || (second !== 0 && second !== 1)) {
      throw new TypeError('biasedCoin must return only 0 or 1');
    }

    if (first === 0 && second === 1) {
      return 0;
    }

    if (first === 1 && second === 0) {
      return 1;
    }
  }

  throw new Error('biasedCoin did not produce a usable unequal pair within maxAttempts');
}
```

## Common Pitfalls

- Returning one biased flip directly instead of using two-flip symmetry.
- Forgetting to discard `(0, 0)` and `(1, 1)`.
- Assuming the source can be deterministic; if it always returns one value, no fair extractor can succeed.

## Why It Surfaces

This is the standard interview solution for a matrix whose rows and columns both increase. The top-right corner is the perfect pivot: if the target is smaller, the whole current column is too large; if the target is larger, the whole current row is too small.

## Worked Example

For `target = 35` in `[[3, 30, 38], [20, 52, 54], [35, 60, 69]]`, start at `38` in the top-right corner. Since `35 < 38`, move left to `30`. Since `35 > 30`, move down to `52`, then left to `20`, then down to `35`, where the search succeeds.

function validateSortedMatrix(matrix) {
  if (!Array.isArray(matrix) || matrix.length === 0 || !matrix.every((row) => Array.isArray(row))) {
    throw new TypeError('matrix must be a non-empty 2D array');
  }

  const width = matrix[0].length;
  if (width === 0) {
    throw new TypeError('matrix rows must not be empty');
  }

  if (!matrix.every((row) => row.length === width && row.every((value) => Number.isFinite(value)))) {
    throw new TypeError('matrix rows must have equal length and contain only finite numbers');
  }
}

function searchInARowWiseAndColumnWiseSortedMatrix(matrix, target) {
  validateSortedMatrix(matrix);

  let row = 0;
  let col = matrix[0].length - 1;

  while (row < matrix.length && col >= 0) {
    const current = matrix[row][col];

    if (current === target) {
      return true;
    }

    if (target < current) {
      col -= 1;
    } else {
      row += 1;
    }
  }

  return false;
}

## Common Pitfalls

- Falling back to row-by-row binary search when the linear staircase walk is simpler here.
- Starting from the wrong corner and losing the one-row-or-one-column elimination rule.
- Confusing this problem with the stricter fully row-major sorted matrix variant.

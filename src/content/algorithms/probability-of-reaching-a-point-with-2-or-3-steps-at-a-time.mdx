## Why It Surfaces

This problem looks like a stair-counting recurrence at first, but the state stores probability mass instead of the number of ways. The key move is to condition on the last jump: you arrive at position `i` either from `i - 2` with probability `p` or from `i - 3` with probability `1 - p`.

## Worked Example

For `N = 5` and `p = 0.2`, there are only two valid move sequences:

- `2 + 3` with probability `0.2 * 0.8 = 0.16`
- `3 + 2` with probability `0.8 * 0.2 = 0.16`

So the final probability is `0.32`.

function probabilityOfReachingAPointWith2Or3StepsAtATime(target, probabilityOfTwoStep) {
  if (!Number.isInteger(target) || target < 0) {
    throw new RangeError('target must be a non-negative integer');
  }

  if (
    typeof probabilityOfTwoStep !== 'number' ||
    !Number.isFinite(probabilityOfTwoStep) ||
    probabilityOfTwoStep < 0 ||
    probabilityOfTwoStep > 1
  ) {
    throw new RangeError('probabilityOfTwoStep must be between 0 and 1');
  }

  if (target === 0) {
    return 1;
  }

  if (target === 1) {
    return 0;
  }

  if (target === 2) {
    return probabilityOfTwoStep;
  }

  let dpMinus3 = 1;
  let dpMinus2 = 0;
  let dpMinus1 = probabilityOfTwoStep;

  for (let position = 3; position <= target; position += 1) {
    const current = probabilityOfTwoStep * dpMinus2 + (1 - probabilityOfTwoStep) * dpMinus3;
    dpMinus3 = dpMinus2;
    dpMinus2 = dpMinus1;
    dpMinus1 = current;
  }

  return dpMinus1;
}

## Follow-up Questions

- Generalize the recurrence to an arbitrary set of step lengths with assigned probabilities.
- Compute the expected number of moves instead of only the hit probability.
- Compare this weighted recurrence with the plain count-of-ways stair DP.

## Common Pitfalls

- Counting valid sequences without multiplying by their move probabilities.
- Forgetting the base cases for unreachable positions like `1`.
- Allowing probabilities outside the range `[0, 1]`.

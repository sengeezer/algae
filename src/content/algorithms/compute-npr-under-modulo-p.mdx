## Why It Surfaces

Modulo counting prompts still begin with the same order question as plain `nPr`. Once the problem is confirmed to be a permutation count, the implementation is just a descending product with a modulo reduction after every multiplication.

## Worked Example

`P(5, 3) mod 7 = (5 * 4 * 3) mod 7 = 60 mod 7 = 4`. Reducing inside the loop reaches the same answer while keeping every intermediate value bounded.

## Reference Implementations

<ExamplePair>

```js
function nPrModulo(n, r, modulus) {
  if (!Number.isInteger(n) || !Number.isInteger(r) || !Number.isInteger(modulus)) {
    return 0n;
  }

  if (n < 0 || r < 0 || r > n || modulus <= 0) {
    return 0n;
  }

  const mod = BigInt(modulus);
  let result = 1n;

  for (let used = 0; used < r; used += 1) {
    result = (result * BigInt(n - used)) % mod;
  }

  return result;
}
```

## Common Pitfalls

- Reaching for modular inverse even though this formula never divides.
- Multiplying many factors first and taking the modulus only at the end.
- Forgetting that `r = 0` should still return `1`.

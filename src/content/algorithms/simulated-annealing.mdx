## Why It Surfaces

Simulated annealing shows up when exact optimization is too expensive and greedy local search gets trapped too easily. Its core idea is simple: at high temperature, explore aggressively; as the system cools, become more selective and keep the best state seen.

## Worked Example

Suppose the state is a single integer and the cost is `(x - 3)^2 + 1`. A simulated-annealing run might start at `x = 9`, explore nearby points like `8`, `10`, `7`, and even accept a temporary setback, but with enough cooling it should keep a best-so-far state near `x = 3`, where the cost is minimal.

function createLinearCongruentialGenerator(seed) {
  let state = (seed >>> 0) || 1;

  return function random() {
    state = (1664525 * state + 1013904223) >>> 0;
    return state / 0x100000000;
  };
}

function simulatedAnnealing(options) {
  const {
    initialState,
    cost,
    neighbor,
    initialTemperature = 1,
    minimumTemperature = 0.0001,
    coolingRate = 0.9,
    iterationsPerTemperature = 100,
    random = Math.random,
  } = options;

  if (typeof cost !== 'function' || typeof neighbor !== 'function') {
    throw new TypeError('cost and neighbor must be functions');
  }

  if (!(initialTemperature > 0) || !(minimumTemperature > 0) || minimumTemperature >= initialTemperature) {
    throw new RangeError('temperatures must satisfy initialTemperature > minimumTemperature > 0');
  }

  if (!(coolingRate > 0 && coolingRate < 1)) {
    throw new RangeError('coolingRate must be between 0 and 1');
  }

  if (!Number.isInteger(iterationsPerTemperature) || iterationsPerTemperature <= 0) {
    throw new RangeError('iterationsPerTemperature must be a positive integer');
  }

  let currentState = initialState;
  let currentCost = cost(currentState);
  let bestState = currentState;
  let bestCost = currentCost;

  for (let temperature = initialTemperature; temperature > minimumTemperature; temperature *= coolingRate) {
    for (let iteration = 0; iteration < iterationsPerTemperature; iteration += 1) {
      const candidateState = neighbor(currentState, random);
      const candidateCost = cost(candidateState);
      const delta = candidateCost - currentCost;

      if (delta <= 0 || random() < Math.exp(-delta / temperature)) {
        currentState = candidateState;
        currentCost = candidateCost;

        if (candidateCost < bestCost) {
          bestState = candidateState;
          bestCost = candidateCost;
        }
      }
    }
  }

  return {
    bestState,
    bestCost,
    finalState: currentState,
    finalCost: currentCost,
  };
}

## Follow-up Questions

- Replace the simple scalar-state example with a permutation neighbor for routing or scheduling problems.
- Tune the cooling schedule and iterations per temperature for faster convergence on a fixed budget.
- Compare simulated annealing with hill climbing and explain why annealing can escape local minima more reliably.

## Common Pitfalls

- Using a cooling rate greater than or equal to `1`, which stops the system from ever cooling.
- Mutating state objects in place and then losing track of which candidate was actually best.
- Treating one seeded run as a proof of optimality rather than a heuristic sample.

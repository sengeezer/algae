## Why It Surfaces

This prompt looks like a brute-force triplet problem, but the real task is spotting the combinatorial pattern. Among the numbers `1` through `2n + 1`, every valid three-term arithmetic progression is determined by its middle value and common difference, so the count collapses to a closed form.

## Worked Example

For `n = 2`, the set is `{1, 2, 3, 4, 5}`. The valid AP triplets are:

- `{1, 2, 3}`
- `{2, 3, 4}`
- `{3, 4, 5}`
- `{1, 3, 5}`

There are `4` valid triplets out of `C(5, 3) = 10` total triplets, so the probability is `4 / 10 = 0.4`.

## Reference Implementations

<ExamplePair>

```js
function probabilityForThreeRandomlyChosenNumbersToBeInAP(n) {
  if (!Number.isInteger(n) || n <= 0) {
    throw new RangeError('n must be a positive integer');
  }

  return (3 * n) / (4 * n * n - 1);
}
```

```ts
export function probabilityForThreeRandomlyChosenNumbersToBeInAP(n: number): number {
  if (!Number.isInteger(n) || n <= 0) {
    throw new RangeError('n must be a positive integer');
  }

  return (3 * n) / (4 * n * n - 1);
}
```

## Common Pitfalls

- Treating `n` as the array length instead of the parameter in `2n + 1`.
- Enumerating every triplet and missing the constant-time closed form.
- Forgetting that the denominator is the total number of unordered triplets.

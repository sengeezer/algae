## Why It Surfaces

Sometimes the task is not to evaluate `phi(n)` once, but to have every totient value from `1` through `n` ready for later use. The sieve-style solution initializes `phi[i] = i` and then lets every prime `p` apply the multiplicative update `phi[multiple] -= phi[multiple] / p` across its multiples.

## Worked Example

For `n = 10`, start with `phi = [0, 1, 2, 3, ... , 10]`. When you encounter prime `2`, update all multiples of `2`; when you encounter prime `3`, update all multiples of `3`; and so on. The final table from `1` through `10` becomes `[1, 1, 2, 2, 4, 2, 6, 4, 6, 4]`.

## Reference Implementations

<ExamplePair>

```js
function eulersTotientFunctionForAllNumbersUpTo(limit) {
  if (!Number.isInteger(limit) || limit < 1) {
    return [];
  }

  const phi = new Array(limit + 1).fill(0);

  for (let value = 1; value <= limit; value += 1) {
    phi[value] = value;
  }

  for (let prime = 2; prime <= limit; prime += 1) {
    if (phi[prime] !== prime) {
      continue;
    }

    for (let multiple = prime; multiple <= limit; multiple += prime) {
      phi[multiple] -= Math.floor(phi[multiple] / prime);
    }
  }

  return phi.slice(1);
}
```

## Follow-up Questions

- Keep the zero index too if later code wants direct `phi[n]` lookup.
- Reuse the same prime-iteration pattern to build other arithmetic-function tables.
- Compare this full table against the repeated-query prime-list approach.

## Common Pitfalls

- Forgetting to initialize `phi[i] = i`, which breaks the multiplicative update formula.
- Starting prime updates at `2 * prime` instead of `prime`, which leaves `phi[prime]` itself wrong.
- Confusing the returned table with primality flags instead of completed totient values.

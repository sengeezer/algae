## Why It Surfaces

This is a compact formula problem. Once you compute

- `AM = (a + b) / 2`
- `GM = sqrt(a * b)`

the harmonic mean follows from `HM = GM^2 / AM`, which is equivalent to the familiar `2ab / (a + b)` when the numbers are non-negative.

## Worked Example

For `a = 5` and `b = 15`:

- `AM = 10`
- `GM = sqrt(75) ≈ 8.660254`
- `HM = 75 / 10 = 7.5`

## Reference Implementations

<ExamplePair>

```js
function harmonicMeanFromArithmeticAndGeometric(a, b) {
  if (![a, b].every((value) => typeof value === 'number' && Number.isFinite(value))) {
    throw new TypeError('Inputs must be finite numbers');
  }

  if (a < 0 || b < 0) {
    throw new RangeError('This implementation expects non-negative inputs');
  }

  const arithmeticMean = (a + b) / 2;
  const geometricMean = Math.sqrt(a * b);
  const harmonicMean = arithmeticMean === 0 ? 0 : (a * b) / arithmeticMean;

  return {
    arithmeticMean,
    geometricMean,
    harmonicMean,
  };
}
```

## Follow-up Questions

- Prove that `HM <= GM <= AM` for positive inputs.
- Return only the harmonic mean once the arithmetic and geometric means are already known.
- Explain why negative inputs are rejected in this version even though the direct harmonic-mean formula can be extended more carefully.

## Common Pitfalls

- Forgetting that the geometric mean requires a non-negative product in the real-number setting.
- Dividing by zero when both inputs are zero unless that case is handled explicitly.
- Rounding the intermediate means too early and losing accuracy in the harmonic mean.

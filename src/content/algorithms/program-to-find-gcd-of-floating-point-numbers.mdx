## Why It Surfaces

This prompt tests whether you can preserve an arithmetic invariant through representation changes. The clean move is to scale both decimals by the same power of ten, compute an integer gcd, and divide the result back by that scale.

## Worked Example

- `0.3` and `0.9` scale to `3` and `9`, whose gcd is `3`, so the answer is `0.3`.
- `0.48` and `0.108` scale to `480` and `108`, or more generally `480` and `108` after aligning decimal places, whose gcd is `12`, so the answer is `0.012`.

function gcd(left, right) {
  let a = Math.abs(left);
  let b = Math.abs(right);

  while (b !== 0) {
    [a, b] = [b, a % b];
  }

  return a;
}

function decimalPlaces(value) {
  const text = value.toString().toLowerCase();
  const [coefficient, exponentText] = text.split('e');
  const fractionLength = (coefficient.split('.')[1] || '').length;
  const exponent = exponentText ? Number(exponentText) : 0;
  return Math.max(0, fractionLength - exponent);
}

function programToFindGcdOfFloatingPointNumbers(left, right) {

  const scaledLeft = Math.round(Math.abs(left) * scale);
  const scaledRight = Math.round(Math.abs(right) * scale);
  return gcd(scaledLeft, scaledRight) / scale;
}

## Common Pitfalls

- Using raw floating-point remainder operations and hoping exact decimal answers fall out reliably.
- Forgetting to align both values to the same power of ten before computing gcd.
- Ignoring the all-zero edge case, where gcd is not defined in the usual positive-divisor sense.

## Why It Surfaces

The naive approach checks every pair and calls gcd each time. The efficient route counts how much each divisor contributes across multiples, and uses totients to measure coprime partner counts.

## Worked Example

- For `n = 4`, the sum is `gcd(1,2) + gcd(1,3) + gcd(1,4) + gcd(2,3) + gcd(2,4) + gcd(3,4) = 7`.
- For `n = 12`, the total gcd-pair sum is `105`.

function buildTotients(limit) {
  const phi = Array.from({ length: limit + 1 }, (_, index) => index);

  for (let value = 2; value <= limit; value += 1) {
    if (phi[value] !== value) {
      continue;
    }

    for (let multiple = value; multiple <= limit; multiple += value) {
      phi[multiple] -= Math.floor(phi[multiple] / value);
    }
  }

  phi[0] = 0;
  if (limit >= 1) {
    phi[1] = 1;
  }

  return phi;
}

function summationOfGcdOfAllThePairsUpToN(n) {
  if (!Number.isInteger(n) || n < 1) {
    throw new RangeError("Expected a positive integer");
  }

  const phi = buildTotients(n);
  const contribution = Array(n + 1).fill(0);

  for (let divisor = 1; divisor <= n; divisor += 1) {
    for (let multiple = divisor * 2; multiple <= n; multiple += divisor) {
      contribution[multiple] += divisor * phi[multiple / divisor];
    }
  }

  let total = 0;
  for (let value = 1; value <= n; value += 1) {
    total += contribution[value];
  }

  return total;
}

## Common Pitfalls

- Enumerating all pairs directly and timing out for moderate constraints.
- Including pairs `(i, i)` when the prompt defines only unordered distinct pairs.
- Forgetting to initialize `phi[1]` correctly in totient construction.

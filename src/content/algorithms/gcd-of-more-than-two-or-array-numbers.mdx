## Why It Surfaces

This prompt checks whether you can generalize Euclid's algorithm instead of re-deriving gcd from scratch. The clean approach keeps a running gcd and folds each new value into it.

## Worked Example

- For `[2, 4, 6, 8]`, the running gcd is `2` after the first pair and never changes again.
- For `[1, 2, 3]`, the running gcd becomes `1`, so the algorithm can terminate early because no later value can increase it.

```js
function gcd(left, right) {
  let a = Math.abs(left);
  let b = Math.abs(right);

  while (b !== 0) {
    [a, b] = [b, a % b];
  }

  return a;
}

function gcdOfMoreThanTwoOrArrayNumbers(values) {
  if (!Array.isArray(values) || values.length === 0) {
    throw new RangeError("Expected a non-empty array of non-negative integers");
  }

  let runningGcd = 0;

  for (const value of values) {
    if (!Number.isInteger(value) || value < 0) {
      throw new RangeError("Array elements must be non-negative integers");
    }

    runningGcd = gcd(runningGcd, value);
    if (runningGcd === 1) {
      return 1;
    }
  }

  return runningGcd;
}
```

## Follow-up Questions

- Why is `0` a useful initializer for a running gcd?
- How would you adapt the routine if the prompt allowed negative numbers explicitly?
- Can you stream the answer if values arrive one at a time instead of in one array?

## Common Pitfalls

- Recomputing divisors from scratch for every array prefix instead of folding gcds.
- Missing the early return once the running gcd becomes `1`.
- Rejecting `0` even though gcd reduction can still be defined sensibly for non-negative inputs.
